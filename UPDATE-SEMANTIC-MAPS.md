# Teneta — семантичні карти

Пакет змін для актуальної версії з головною сторінкою, каталогом та EN/УКР.
Це не повний проєкт і не копія застарілого UI. Зміни в GitHub не вносились.

## Встановлення

Почніть із збереженої роботи та чистої робочої директорії:

```sh
git switch main
git pull --ff-only origin main
git switch -c feat/semantic-maps
```

Розпакуйте **вміст** архіву в корінь вашої Teneta, поруч із `package.json`.
Об’єднайте папки та замініть включені файли. Нічого видаляти не потрібно.
Архів не містить `node_modules`, `.git`, `.env`, `dist` або нових залежностей.

```sh
node --test
npm run lint
npm run build
npm run dev
```

Після перевірки:

```sh
git add src tests UPDATE-SEMANTIC-MAPS.md CHECKS-SEMANTIC-MAPS.md
git commit -m "feat: add semantic maps and organization graph navigation"
git push -u origin feat/semantic-maps
```

Створіть PR до `main`, перевірте зміни та змерджіть. Наявний workflow GitHub Pages не потрібно змінювати.

## Сторінки та навігація

- `/Teneta/` або `#/` — головна сторінка, як і раніше.
- `#/catalogue` — каталог.
- `#/maps` — загальна семантична мережа.
- `#/maps?organization=ENT_043` — локальна карта організації.

У шапці з’являється третя сторінка. У вікні організації каталогу — посилання
«Відкрити карту організації». Подвійний клік на вузлі організації на полотні
також відкриває її карту. У правій панелі доступні карта та звичайний профіль.
Підтримуються прямі hash-посилання, Назад/Уперед та зміна ID без зміни сторінки.

Каталог і карти отримують **один спільний набір даних**, ліниво завантажений
після першого переходу до однієї з цих сторінок. На головній запиту немає.
Фільтри та сортування каталогу при переходах не скидаються. Граф охоплює весь
завантажений набір, а не тільки поточну сторінку чи відфільтровані рядки таблиці.

## Керування графом

- Перетягування фону — переміщення огляду; перетягування вузла — його позиції.
- Коліщатко, кнопки +/− або жест двома пальцями — масштабування.
- Кнопка з рамкою — вмістити граф. На сфокусованому полотні: Home — вмістити,
  стрілки — переміщення, +/− — масштаб, Escape — прибрати вибір.
- Клік — вибір вузла та його зв’язків. У списку вузлів можна зробити те саме
  клавіатурою, без використання полотна.
- Пошук підсвічує збіги; список результатів дозволяє центрувати їх на полотні.
  Пошук не змінює вихідні дані та не видаляє решту мережі.
- Фільтри типів прибирають відповідні вузли та їхні ребра. Вузли організацій
  залишаються. Сховані вузли не утворюють невидимих переходів локальної карти.
- Локальна карта має глибину 1–5 переходів, за замовчуванням 2.
- «Відстань» перераховує компонування; підписи можна вимкнути.

На малих екранах панель параметрів і вузлів розташовується під полотном та
прокручується окремо. У списку DOM одночасно показується порція вузлів —
«Показати ще» відкриває наступну. Це **не обмеження кількості вузлів на графі**.

## Звідки беруться вузли й зв’язки

`src/graph/model.js` перетворює нормалізовані записи каталогу на індексований
граф. Оригінальні об’єкти JSON не змінюються.

| Дані | Представлення |
|---|---|
| `meta.entity_id`, профіль | Вузол організації, ID, назва, готові ризик/бал |
| `contacts_and_web.websites` | Вузли сайтів |
| `corporate_emails`, `phones` | Вузли корпоративних контактів |
| `vacancies` | Вузли вакансій, прив’язані до своєї організації |
| `vacancies[].key_skills` | Навички, прив’язані до вакансії та організації |
| `graph_nodes_and_edges.connections` | Зв’язки, прямо записані у даних |
| `graph_nodes_and_edges.nodes/edges` | Додатковий явний формат вузлів/ребер |

Текстові описи, аналіз, місце, ідентифікатори й інші атрибути доступні у профілі;
кожне окреме поле чи число не перетворюється на штучний вузол. Особисті записи
`recruiters` не включаються у граф.

### Ідентичність і кластери

Відомі `entity_id` та однозначні ІПН зв’язуються з наявними організаціями.
Назва сама по собі не замінює ідентифікатор компанії. Посилання на зовнішні
сутності без повного профілю показуються окремими вузлами-згадками, а не
вигаданими повноцінними компаніями. Повтор одного й того самого зовнішнього
ідентифікатора/токена `target` створює спільний вузол згадки. Це відображення
тверджень джерела, а не незалежна перевірка тотожності чи підпорядкування.

Точний збіг корпоративної пошти, повного номера або URL може створити спільний
вузол. В інспекторі зазначено, що це **збіг у даних, не доказ власності**.
URL нормалізується за хостом, портом, шляхом і query; протокол, фрагмент і `www`
не розрізняються. Різні сторінки одного хоста не зливаються автоматично.
Головні сторінки типових платформ на кшталт hh.ru не з’єднують усі організації.
Неповні номери та номери з розширеннями не об’єднуються евристично.

Спільне місто, галузь, бал, джерело hh.ru або типова навичка **не створюють
корпоративних зв’язків**. Описові напрями діяльності (`OPERATES_IN_DOMAIN` тощо)
та навички залишаються в межах своєї організації. Зв’язні компоненти графа
компонуються окремими кластерами без штучних ребер між ними. Після зміни
фільтрів кластери перераховуються для видимого графа.

### Поточний формат connections

Для прямого зв’язку з іншою організацією:

```json
{
  "graph_nodes_and_edges": {
    "node_type": "Company",
    "connections": [
      { "relation": "SUPPLIES", "target": "ENT_002" },
      { "relation": "PART_OF", "target_id": "HOLDING_001",
        "target": { "id": "HOLDING_001", "name": "Назва з джерела" } },
      { "relation": "OPERATES_IN_DOMAIN", "target": "Domain_from_source" }
    ]
  }
}
```

Це **приклад контракту**, не додані у ваш каталог результати. Відомі
`target.entity_id`, `target.id`, `target.inn` також підтримуються. Нові назви
зв’язків показуються мовою джерела; базові типи мають EN/УКР підписи.
Для явного формату `nodes/edges` кожен вузол має `id` та необов’язкові `label`,
`name`, `url`; кожне ребро — рядкові `source`, `target`, `relation`.
Невідомі кінці таких ребер пропускаються з лічильником, а не домальовуються.
У панелі зв’язку можна переглянути ID запису, шлях до поля JSON і посилання
на джерело, якщо воно було у даних. Допускаються лише HTTP/HTTPS-посилання.

## Дані не замінені

`public/data/organizations.json` та `organizationService.js` не змінені.
Записи `meta.is_demo: true` як і раніше виключені. З наявним файлом видно
**1 організацію, 11 вузлів, 10 ребер, 1 кластер**. Тестові великі мережі
існують тільки у тестах — не у `public/data` і не на вашому сайті.
Формула ризику, готовий score та межі 65/85 не змінюються.
Не перенесено жодних env-файлів чи підключення до ноутбука колеги.

## Реалізація та масштаб

Canvas 2D малює мережу без окремого DOM-елемента для кожного вузла. На малих
масштабах підписи приглушуються/пропускаються, але вузли та ребра не відкидаються.
Компонування: детерміноване початкове розташування, локальне відштовхування,
пружини ребер, потім пакування компонентів з проміжками. Немає повного
попарного циклу O(V²). Основне уточнення розташування виконується у Web Worker,
що припиняється при зміні графа чи виході зі сторінки.

Якщо Worker не завантажився, залишається доступне початкове компонування з
відповідним статусом. Переміщення і вибір працюють також у цьому режимі.
Worker не має права змінювати JSON, оцінки чи зв’язки — він повертає координати.
Після ручного переміщення/масштабування пізня відповідь Worker не стрибає
камерою та не перезаписує ручну позицію.

Це клієнтська карта всіх **завантажених** записів, не серверний graph engine
і не обіцянка необмеженої кількості записів. Для сотень тисяч/мільйонів вузлів
потрібні окремі рішення для серверних зрізів, прогресивного завантаження й
рендерингу. Виміряні сценарії наведені у `CHECKS-SEMANTIC-MAPS.md`.
